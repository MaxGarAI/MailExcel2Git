# 0.8.2: сравнительные листы и привязка фото

Воспроизведение выполнено на двух MSG, предоставленных пользователем. Excel-вложения
извлечены утилитой QA без подключения к Outlook и без изменения писем.
Исходники и результаты с рабочими данными не включаются в Git и дистрибутив.

## Причины отказа

Первое вложение содержало 17 расчётных товаров, фото-лист и вспомогательную таблицу
с двумя наборами колонок «артикул / фото / наименование». Она не содержала артикулов
из расчётной таблицы, но прежний поиск заголовка выдавал SHEET_SCHEMA и PHOTO_TABLE.
Это отклоняло весь файл, а сообщения NEWEST_ATTACHMENT_REJECTED повторялись для товаров.
FIELDS_SKIPPED были предупреждениями о лишних полях, а не причиной отказа.

Второе вложение содержало 6 товаров. У последнего фото номер начальной строки
указывал на предыдущий товар, но rowOff был больше её высоты. Фактическая картинка
находилась в следующей строке. Старый код не переносил rowOff и ошибочно выдавал
PHOTO_SPANS_PRODUCTS. В результате оба вложения отклонялись целиком.

## Исправление

SourceTables распознаёт роли листов до строгой проверки колонок. Сравнительная
таблица пропускается с предупреждением только при доказанном отсутствии связи
с импортируемыми артикулами. Имя листа не является исключением. Если артикул связан
с заказом или его значение неизвестно из-за отсутствующего кэша, ошибка сохраняется.
Неоднозначные основные таблицы остаются ошибкой. Нормализация, привязка фото и сбор
известных артикулов используют одну классификацию.

RowGeometry переносит избыточное смещение по высотам строк для одноточечных
и двухточечных якорей. Скрытые строки используют свою логическую высоту ht,
чтобы фильтр не менял идентичность товара. Допускается только краевой выход,
не превышающий одновременно 4 pt и 2% высоты изображения. Существенное пересечение
разных товаров остаётся ошибкой. Реальные примеры со скрытыми строками и небольшим
выходом за границы учтены в регрессиях.

## Проверки

- 222 pytest-теста успешно; Ruff без ошибок; строгий Mypy — 93 исходных модуля.
- Новые тесты: несвязанный/связанный сравнительный лист, неоднозначная основная
  таблица, неизвестный артикул, перенос смещения на одну/несколько строк,
  скрытая строка, допустимый край и существенное пересечение.
- Разбор обоих новых вложений: 23 товара, 23 фото, 23 назначения сезона, ошибок 0.
- Прежние 13 вложений: 90 товаров, 90 фото, 7 коллажей; 82 товара в корректных
  вложениях. Остаются только прежние 3 ошибки неизвестных сезонов в 2 вложениях.
  Контрольные суммы 27 прежних исходных файлов не изменились.
- Нативная приёмка Excel: перенос сезона, сохранение/замена фото, сортировка,
  фильтры, даты, ошибки Excel, повтор и backup успешно проверены.
- GUI/CLI упакованного приложения, хеши 1790 файлов и соответствие исходников
  проверены tools/verify_windows_package.py.

## Полный импорт двух писем через EXE

На отдельной копии исходной общей книги, с отдельными рабочими каталогами и PATH
без Python выполнен import-excel из манифеста двух присланных MSG:

| Результат | Количество |
|---|---:|
| Обработано писем | 2 |
| Допущено вложений | 2 |
| Добавлено товаров | 6 |
| Обновлено товаров | 17 |
| Пропущено товаров | 0 |
| Добавлено фото | 6 |
| Заменено фото | 17 |
| Ошибок | 0 |

Проверены сохранённые значения и нативные фото всех 23 товаров. Повтор через EXE
не изменяет SHA-256 книги: 23 товара без изменений, committed=false. Два исходных MSG,
два извлечённых XLSX и исходная общая книга сохранили контрольные суммы.
Предупреждения о полях без целевых столбцов остаются согласно решению пользователя.

Устройства и новые версии Office по-прежнему требуют целевой приёмки. Исправление
не отключает запреты неоднозначных артикулов, неизвестных сезонов и конфликтующих фото.
