# Этап 8: Windows EXE — результаты проверки

Версия 0.8.0, 15 октября 2026 года. Проект находится в перенесённой папке на диске D.
Этап 7 опубликован отдельным коммитом; этот этап добавляет дистрибутив и приёмку EXE.

## Автоматические проверки

207 pytest-тестов успешно. Ruff без ошибок. Строгий Mypy проверяет 89 исходных модулей.
Pip check не обнаружил несовместимых установленных зависимостей.
Добавлены проверки сохранения первичной ошибки при отказах Close и Quit.
Проверены первый запуск frozen-профиля, сохранение пользовательских настроек
при следующем запуске, явный --config и независимость от текущего каталога.
Тесты GUI проверяют отзывчивость настоящего Tk, запрет второго запуска, отмену
и ожидание при закрытии. Ошибки получения писем не теряются при успешной записи
других вложений. Неверный путь общей книги не инициирует получение писем.

Нативный сценарий `tools/verify_master_excel.py` повторно успешно выполнен:
перенос сезона, отсутствие нового фото, одинаковое/изменённое фото, типизированные
ошибки Excel, дата 1904, сортировка и фильтрация изображения в ячейке,
повторный импорт и восстановление последовательных backup.

## Проверка готовых EXE

Оба EXE запущены из другой папки, с отдельным LOCALAPPDATA, без PYTHONPATH,
PYTHONHOME и VIRTUAL_ENV, с PATH только на System32. Версия и diagnose завершаются
кодом 0. Это изоляционная проверка на текущем Windows, а не чистая виртуальная машина.

Графический EXE создал настоящее окно 1120 × 760 со встроенным Tcl/Tk 8.6.15.
Проверены отображение семи управляющих кнопок и отсутствие выхода за границы панелей.
После проверки окно корректно закрыто. Интерфейс не проверялся по скриншоту:
инструмент Windows Computer Use недоступен в этой сессии.

Через упакованную программу выполнен импорт на отдельной копии общей книги:
13 писем, 10 корректных вложений, 68 новых товаров, 5 обновлённых, 17 пропущенных.
Отказы ожидаемые: неизвестные сезоны и отсутствующая зимняя пара; исходная книга
не используется как цель проверки. Сведения о фото и проверка сохранённых значений
проходят тот же verifier, что при запуске из исходников.

Финальный EXE повторно обработал тот же набор: 73 товара без изменений,
committed=false, SHA-256 книги не изменился. Затем restore-backup восстановил
проверочную книгу до точного исходного SHA-256. Журналы и JSON с рабочими данными
остаются в исключённых из Git каталогах.

## Обнаруженный сбой Excel и исправление

При дополнительном прогоне промежуточной сборки Windows зарегистрировала падение
EXCEL.EXE 16.0.20326.20232 с 0xc0000005. RPC оборвался при оформлении добавляемой
строки. Проверочная общая книга осталась с исходным SHA-256, backup проверен;
исходные файлы не использовались как цель записи. Временная рабочая копия могла
остаться заблокированной до завершения аварийного процесса Office.

Убрано копирование целых строк через буфер обмена. Копируются только форматные
диапазоны таблицы, исключая столбец нативного фото. Для фото-ячейки стиль,
выравнивание, заливка и границы переносятся отдельно без копирования изображения.
Порядок применения Pattern и LineStyle сохраняет отсутствие заливки/границы.
Закрытие COM-сеанса теперь сохраняет исходное исключение, даже если Close/Quit
тоже завершились ошибкой; единственная ошибка закрытия не подавляется.

Регрессия проверена в реальном Excel на нативном фото: соседняя строка не получает
копию изображения, исходный хеш фото сохранён, заливка и границы совпадают.
После исправления финальный EXE снова выполнил полный импорт: 68 добавлений,
5 обновлений, 17 пропусков. Все 27 исходных файлов сохранили SHA-256.
Проверка комплекта воспроизводится `tools/verify_windows_package.py --source-root .`;
путь комплекта передаётся первым позиционным аргументом.

Сам факт этого исправления не означает, что приложение может предотвращать
любые внутренние сбои Office: сохранение выполняется через проверяемую копию.

## Целевая приёмка и ограничения

Реальный Outlook с учётной записью и Office Professional Plus 2024 на этом устройстве
не проверены. Перед ежедневным использованием на другом устройстве выполните
сценарии из windows-user-guide.md на отдельной копии книги, включая сортировку фото
и восстановление. Чистая Windows без установленного Python также требует приёмки;
успешный запуск с изолированным PATH подтверждён выше.

EXE не подписан цифровой подписью. Сборщик закрепляет конфигурацию и зависимости,
но не обещает побитово одинаковые ZIP/PE при разных сборках. Переносится вся папка
или ZIP, не один EXE. Для импорта нужны установленный Excel и классический Outlook;
новый Outlook не поддерживается. Файлы конфигурации пользователя при обновлении
сохраняются, поэтому новые стандартные маршруты не внедряются поверх них автоматически.
