````markdown
## Установка для разработки

В PowerShell из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

`requirements.txt` содержит рабочие зависимости; `requirements-dev.txt` добавляет
проверки качества. Если присутствует `requirements-lock.txt`, он фиксирует версии
проверенного окружения и устанавливается вместо `requirements-dev.txt` для его
точного воспроизведения. `tkinter` входит в стандартную Windows-установку Python.

## Запуск этапа 1

```powershell
.\.venv\Scripts\python.exe main.py --config config/default.toml
```

Команда проверяет настройки, создаёт рабочие каталоги и журнал, проверяет наличие
библиотек. Если общая книга не выбрана, сообщает предупреждение. Не подключается
к Outlook/Excel, не изменяет и не сохраняет книги.

Для проверки своей книги передайте абсолютный путь:

```powershell
.\.venv\Scripts\python.exe main.py --config config/default.toml --workbook "D:\вайбкодин\Почта_сводник\=РАССЧИТАНО= ВЕСНА  ВЕСНА-ЛЕТО и ПАСХА 08.10.2026.xlsx"
```

Для персональных настроек скопируйте `config/default.toml` в `config/local.toml`
и задайте `application.workbook`. `local.toml` исключён из Git.
Каждый конфигурационный файл — полный документ; автоматического слияния нет.
Относительные пути в TOML считаются от папки файла настроек. Относительные пути
аргументов CLI считаются от текущего рабочего каталога.

`--data-dir` переопределяет рабочий каталог. По умолчанию при запуске из исходников
это `.runtime/`, содержащий `logs`, `backup`, `work`, `reports`.
В EXE данные хранятся в `%LOCALAPPDATA%\KuchenlandImporter\data`, настройки — в `config` рядом.

Коды завершения: `0` — проверка успешна, возможны предупреждения;
`1` — диагностика обнаружила проблемы; `2` — ошибка запуска/настроек/аргументов;
`3` — непредвиденная ошибка. `--version` работает без конфигурации.

## Получение писем — этап 2

На компьютере с настроенным классическим Outlook откройте основное окно и выделите
письма в списке. Затем запустите из корня проекта:

```powershell
.\.venv\Scripts\python.exe main.py capture-outlook --config config/default.toml
```

Outlook автоматически не запускается. Для этой команды общая книга не требуется.
Читаются идентификаторы, тема, дата получения и отправитель. Excel-вложения
`.xlsx`, `.xlsm`, `.xls`, `.xlsb` сохраняются в `.runtime/work/<run_id>/mail-NNNN/`.
Формат файла пока определяется по расширению; его содержимое проверяется на этапе 3.
Небезопасные исходные имена никогда не используются для построения пути сохранения.

`manifest.json` содержит данные писем, позиции в исходном выделении, оригинальные
имена вложений, относительные пути, SHA-256 и ошибки. Время получения записывается
в UTC. Адрес Exchange может быть служебным адресом, который вернул Outlook;
он не подменяет поставщика из таблицы. Тело письма не читается и не сохраняется.
Отчёт содержит служебные данные и хранится локально вне Git.

Корректные вложения сохраняются даже при ошибках других вложений. Пустые и
неполностью сохранённые файлы не включаются в результат; временные файлы удаляются,
а невозможность их удаления явно сообщается как ошибка. Повторный запуск получает
свой каталог; предыдущие результаты не перезаписываются.
Это получение исходных данных, а не импорт товаров в общую книгу.

Для `capture-outlook`: `0` — есть сохранённые вложения и нет ошибок;
`1` — частичные ошибки либо нет Excel-вложений; `2` — запуск/Outlook недоступен;
`3` — непредвиденная ошибка. Предупреждения также выводятся при успешном запуске.
Если невозможно сохранить JSON-отчёт, полученные файлы остаются в каталоге запуска.
Предоставленные MSG пока не открываются этой командой: она читает выделение Outlook.

## Предварительный разбор Excel — этап 3

Передайте манифест, созданный командой capture-outlook:

```powershell
.\.venv\Scripts\python.exe main.py preview-excel --config config/default.toml --manifest "ПОЛНЫЙ_ПУТЬ_К_manifest.json"
```

Словарь столбцов находится в `config/columns.toml` рядом с TOML-настройками приложения.
Артикул/Article/SKU/Item No приводятся к одному полю. Поддерживаются многоуровневые
и объединённые заголовки исследованных шаблонов. Порядок именованных столбцов
не влияет на поиск полей. Нераспознанные поля сохраняются с префиксом source:;
безымянные столбцы получают исходный номер, для их автоматического переноса потребуется
явное сопоставление на этапе 6. Неоднозначные обязательные столбцы не угадываются.

Поставщик и сезон берутся из строки расчётной таблицы. Поля фото-листа соединяются
по артикулу и сохраняются с префиксом photo:. Для извлечения изображений используется
отдельная команда preview-photos (этап 5).
Числовые артикулы с простым форматом 00000 восстанавливают ведущие нули;
текстовые артикулы сохраняют регистр и нули. Распознаваемые цены становятся Decimal,
даты начала продаж — date; пояснительные текстовые значения сохраняются.

Ошибки Excel остаются типизированными `{type: excel_error, code: ...}`, а не обычным
текстом. Они отражаются предупреждениями и не отменяют строку по согласованному правилу.
Если отсутствует сохранённый результат формулы, строка отмечается ошибкой:
openpyxl не вычисляет формулы. Пустой текстовый результат формулы — допустимое значение.

XLSX/XLSM читаются без сохранения книги. XLS/XLSB используют отдельный экземпляр
Excel, отключают VBA через AutomationSecurity и открывают книгу ReadOnly без обновления
ссылок. Нативная совместимость XLS/XLSB, политики Excel 4.0 macros и особенности
защищённых файлов требуют проверки на целевой машине; листы макросов не поддерживаются.
При отсутствии подходящего Excel файл попадёт в отчёт с ошибкой.

SHA-256 вложений проверяется перед чтением. JSON-отчёт записывается в .runtime/reports;
повреждённая книга не блокирует другие вложения. Счётчик товаров — число прочитанных
записей предпросмотра, не число импортированных товаров. eligible_for_import отражает
валидность чтения; финальная проверка сезона, дублей между письмами и записи ещё впереди.
Исходные файлы и общая книга не изменяются. Лимиты: 50 МБ на OOXML-файл,
100000 строк и 512 столбцов на лист; произвольные шаблоны требуют настройки профиля.

Для QA предоставленных Unicode MSG без Outlook есть `tools/extract_msg_samples.py`.
Это ограниченная утилита исследования материалов, а не универсальный MSG-импортёр.
Она сохраняет вложения и совместимый манифест в новый каталог, читая Windows OLE
только для чтения. Исходные MSG проверяются SHA-256. Команда для предоставленной папки:

```powershell
.\.venv\Scripts\python.exe tools/extract_msg_samples.py "D:\вайбкодин\Почта_сводник" ".runtime\msg-qa-new"
```

## Предпросмотр сезонных маршрутов — этап 4

Команда `preview-seasons` читает исходные вложения из манифеста и для каждой строки
назначает расчётную вкладку и соответствующий лист ФОТО. Для уже извлечённых
предоставленных материалов запуск из корня проекта:

```powershell
.\.venv\Scripts\python.exe main.py preview-seasons --config config/default.toml --manifest .runtime/msg-stage3-verified/manifest.json
```

Для писем Outlook передайте путь к `manifest.json` своего запуска capture-outlook.
Настроенные псевдонимы сопоставляются без учёта регистра, с нормализацией пробелов
и вариантов тире. Поддержан исследованный формат `(У) 2. ВЕСНА-ЛЕТО 2027`:
пометки `(У)`/`(Д)`, порядковый номер и один четырёхзначный год отделяются от названия.
Другие пометки, диапазоны годов и составные сезоны без псевдонима не угадываются.
Точное совпадение с настроенным псевдонимом имеет приоритет перед разбором пометок.

Маршрут с id `winter` при месяце начала продаж 12 меняется на маршрут `spring`.
Эти идентификаторы используются декабрьским правилом; если настроен winter,
нужен spring. Имена вкладок и псевдонимы обоих маршрутов можно менять.
Месяц определяется из date/datetime, календарных дат ДД.ММ.ГГГГ, ДД/ММ/ГГГГ,
ГГГГ-ММ-ДД, месяца с годом ММ.ГГГГ/ГГГГ-ММ, ДД.ММ и полного русского/английского
названия месяца, в том числе с годом. Нераспознанный текст, числа без формата даты,
пустые значения и ошибки Excel не интерпретируются произвольно.
При неопределённом начале продаж Зима остаётся на зимней паре с предупреждением.

НГ и ВСЕСЕЗОННЫЙ сейчас не настроены по решению пользователя. Любой неизвестный
сезон делает всё вложение непригодным для будущего импорта, включая остальные
корректные строки этого вложения. Другие вложения продолжают обрабатываться.
Предпросмотр сохраняет все прочитанные строки и объясняет ошибки.

Отчёт `.runtime/reports/season-preview-<run_id>.json` содержит `routing` каждой
строки: исходный сезон/год, итоговый сезон/год, месяц, правило и точную пару вкладок.
Неопределённый маршрут — null. `routes_assigned` считает назначения, в том числе
в ошибочных вложениях; `eligible_product_count` считает только товары из полностью
корректных вложений. Эти числа не означают запись товаров в общую книгу.
Коды завершения: 0 — нет ошибок, 1 — есть ошибочные вложения/строки,
2 — ошибка входных данных или настроек, 3 — непредвиденный сбой.

Исходная строка и её поля сохраняются без изменения; итоговый сезон находится
в назначении маршрута и должен использоваться будущим адаптером записи.
Исходный год сохраняется отдельно. По согласованному правилу декабрьский переход
повышает его на один: Зима 2026 → Весна 2027. Если в названии года нет, используется
год распознанной даты начала продаж. Если нет обоих, Весна назначается без года
с предупреждением TARGET_SEASON_YEAR_UNKNOWN. Для остальных маршрутов год названия
сохраняется; при его отсутствии год из даты автоматически не добавляется.
Наличие/схема вкладок общей книги пока не проверяются, новые листы не создаются;
это этап 6. Изображения и выбор самого нового письма относятся к этапам 5–6.

## Настройки сезонов

Каждый `[[routes]]` содержит уникальный `id`, список названий `aliases`,
имя расчётной вкладки `calculation_sheet` и листа `photo_sheet`.
Можно добавлять новые маршруты без изменения моделей и исходного кода.
Неоднозначные названия, повторные назначения вкладок и опечатки в ключах отклоняются.

Настроены Весна/Весна-лето, Пасха, Лето/Лето-осень, Осень, Зима.
В исходной общей книге зимней пары нет: на этом этапе конфигурация только описывает
её, а вкладки не создаются. Создание пары по выбранному шаблону и редактор сезонов
относятся к этапам 6–7.

Адаптеры чтения `.xlsx`, `.xlsm`, `.xls`, `.xlsb` реализованы на этапе 3.
Реальные вложения проверены для XLSX; тестовые XLS/XLSB проверены через установленный
Microsoft 365. Приёмка произвольных файлов и Office 2024 остаётся отдельной проверкой.
Файлы с паролем не обещаются к поддержке без отдельного решения.

## Фотографии — этап 5

Для предоставленного набора материалов:

```powershell
.\.venv\Scripts\python.exe main.py preview-photos --config config/default.toml --manifest .runtime/msg-stage3-verified/manifest.json
```

Для Outlook используйте манифест своего запуска capture-outlook. Команда объединяет
проверки таблиц, сезонов и фото. Вложения и общая книга не изменяются. JSON-отчёт
находится в `.runtime/reports/photo-preview-<run_id>.json`, подготовленные PNG —
в `.runtime/work/photo-preview-<run_id>/`.

Изображения привязываются к артикулу строки по именованному столбцу Фото/Photo/Image.
Картинки в других столбцах не считаются фотографиями товара. Поддержаны DrawingML
oneCellAnchor/twoCellAnchor и нативные localImage в ячейке с rich-data metadata.
Используются сохранённые пиксели с учётом EXIF, обрезки, поворота и отражений.
Фото, пересекающее строки разных артикулов, — ошибка, а не случайный выбор товара.
Внешние ссылки не загружаются из сети. Группы/абсолютные привязки требуют профиля
и дают явную ошибку на фото-листе; повреждённые изображения блокируют своё вложение.

Несколько разных фото собираются в коллаж по решению пользователя. Одинаковые
нормализованные изображения удаляются из набора. Порядок частей коллажа определяется
хешем, поэтому изменение порядка объектов не создаёт ложную замену. Сетка использует
плитки 512×512, белый фон и сохранение пропорций; для одиночного изображения размер
не уменьшается. `image_count` — число разных изображений в подготовленном фото.
Лимиты: до 16 исходных изображений товара, 20 МБ на картинку, 40 Мп на декодирование.
Объём распакованного OOXML ограничен 256 МБ/10000 частей, XML-часть — 16 МБ.

Хеш включает размеры и RGBA-пиксели, поэтому перекодирование без изменения пикселей
не меняет результат. Решение фото: add/replace/keep/none. Если нового фото нет,
прежнее сохраняется; одинаковое не заменяется; изменённое заменяется. Ошибка чтения
не считается отсутствием нового фото: такое вложение исключается из импорта.
Сравнение с фото общей книги и применение решения будут подключены на этапе 6.

XLS/XLSB для чтения фото конвертируются в отдельную временную XLSX-копию через Excel.
Источник открывается ReadOnly без обновления ссылок, VBA отключён; копия удаляется
после чтения. Источник не сохраняется. Политики XLM/защищённых файлов остаются
ограничениями целевой среды. Сеансы чтения/записи Excel должны выполняться последовательно.

Адаптер InCellPictureWriter работает только на рабочей копии и одной необъединённой
ячейке. Сначала конвертация инициализирует нативный формат, затем прямая вставка
сохраняет исходные пиксели PNG. Если Excel не поддерживает операции, возникает ошибка;
подмена плавающим изображением не применяется. При ошибке рабочую копию нужно отбросить.
Сохранённый результат должен проверяться перед заменой общей книги на этапе 6.

Нативные проверки на новых тестовых книгах, в ранее не существовавших каталогах:

```powershell
.\.venv\Scripts\python.exe tools/verify_incell_excel.py .tmp/incell-acceptance-new
.\.venv\Scripts\python.exe tools/verify_legacy_photos.py .tmp/legacy-acceptance-new
```

В текущем Microsoft 365 16.0.20430.20092 подтверждены правильная ячейка, нативная
метаинформация, отсутствие плавающей картинки и точный хеш после save/reopen.
Проверки на Office Professional Plus 2024 ещё требуются. Макросы VBA не используются.

## Запись в общую книгу — этап 6

Закройте выбранную общую книгу в Excel. Команда `import-excel` принимает тот же
`--manifest`, что предпросмотр, и обязательный путь книги из конфигурации либо
`--workbook`. Настройки записи находятся в `config/writing.toml`; отдельный файл
можно указать через `--write-config`.

```powershell
.\.venv\Scripts\python.exe main.py import-excel --config config/local.toml --manifest .runtime/work/<run_id>/manifest.json
```

Зафиксированные правила: ручные значения и формулы вне вложения сохраняются;
неизвестные поля пропускаются с предупреждением; недостающая сезонная пара
исключает целое вложение. Новые вкладки и столбцы не создаются автоматически.
Все распознанные товарные листы участвуют в глобальном поиске артикула, кроме
исключённых листов. Одна существующая строка товара восстанавливается до пары
с предупреждением; неоднозначные дубли отклоняются.

Старые строки удаляются, новые вставляются в расчётную и фото-вкладку. Значения
поставщика не становятся формулами. При смене сезона сохранённые ссылки фото-формул
перенаправляются на новую расчётную вкладку. Новые/сохранённые фото записываются
нативно; выбранная старая фотография сохраняет точный хеш пикселей.
Данные `Цена под TARGET PRICE` не удаляются. Сохранение книги выполняет Microsoft Excel,
openpyxl используется только для чтения и контроля.

Перед записью создаются SHA-256-проверяемый backup и рабочая копия. Исходная книга
заменяется только после закрытия Excel и проверки записанных полей/ошибок/фотографий.
Lock с PID блокирует одновременные запуски инструмента; открытая/изменившаяся во время
импорта книга не заменяется. Системная ошибка записи отменяет всю транзакцию;
ошибки конкретных вложений исключают их при подготовке, остальные импортируются.
Резервные копии не удаляются автоматически.

Скрытый лист `_KL_IMPORT_STATE` хранит последнее время письма в UTC и fingerprint
для повторного импорта. Не удаляйте его. Повторное письмо не создаёт дублей, старое
не заменяет новое. Отличающиеся данные с одинаковым временем — конфликт.
Если ошибочный файл не позволяет определить все артикулы, более старые кандидаты
блокируются до исправления источника. Для ручной книги без состояния сравнивается
доступная календарная дата; её точное историческое время программа не придумывает.
Пользовательские даты писем записываются в местном часовом поясе Windows.

Результат сохраняется в `.runtime/reports/import-<run_id>.json`: счётчики после commit,
пригодность вложений, ошибки и пропущенные поля. `error_count` — число диагностических
сообщений, а не число писем. Код 1 допускает сохранённый частичный результат;
`committed` явно показывает, заменена ли книга. При повторном запуске без изменений
committed=false. Код 2 означает отказ/отмену записи или неверный ввод.

Для восстановления запустите `restore-backup` с тем же `--config`/`--workbook`
и аргументом `--journal`, указывающим на JSON журнала в папке backup. Команда сверяет
хеши и сохраняет дополнительный backup текущего результата. При последующих ручных
изменениях она отказывает, чтобы их не потерять. Если после аварии остался lock,
сначала используйте `recover-lock` с тем же журналом: работающий процесс не прерывается.

Приёмочная проверка без рабочих данных:

```powershell
.\.venv\Scripts\python.exe tools/verify_master_excel.py .runtime/master-acceptance
```

Каталог должен быть новым. Скрипт создаёт собственные книги и проверяет перенос,
фото, ошибки, даты, сортировку/фильтры, повтор и восстановление.
Не используйте общую книгу как каталог этой проверки.

Запись поддерживает семь классических ошибок Excel: `#NULL!`, `#DIV/0!`,
`#VALUE!`, `#REF!`, `#NAME?`, `#NUM!`, `#N/A`. Иные ошибки в записываемых
полях исключают вложение с объяснением в отчёте. Общую книгу перед импортом
необходимо закрыть. Проверена установленная сборка Microsoft 365;
Office Professional Plus 2024 и Outlook требуют приёмки на целевом устройстве.

## Исправление 0.8.1: размер общей книги

Убран жёсткий порог 50 МБ для XLSX/XLSM во всех путях чтения. Ранее один читатель
использовался и для вложений, и для общей книги, а сообщение всегда называло файл
«вложением». Поэтому вложение в 5 МБ могло сопровождаться отказом при чтении
большой общей книги. Теперь ошибки называют этап и исходное имя общей книги.

Общая книга использует отдельный профиль чтения: без ограничения суммарного
распакованного объёма, с бюджетом 100000 частей OOXML и 64 МБ на XML-часть.
Для исходных вложений сохранены структурные бюджеты: 10000 частей и 256 МБ
распакованного содержимого. Физический размер файла 50 МБ больше не проверяется.
Остальные проверки ячеек и изображений сохраняются. Прочитаны настоящий XLSX
размером больше 50 МБ с 17 фото и компактный архив с большим распакованным содержимым.

Обновление: распакуйте ZIP последней версии в новую папку и запускайте EXE из неё.
Личные настройки из LOCALAPPDATA сохраняются. Резервная копия после отказа
остаётся доступной; если запуск не дошёл до записи, восстанавливать книгу не нужно.
Полные файлы и проверки исправления: `docs/fix-0.8.1-code.md`, `docs/fix-0.8.1-validation.md`.


## Исправление 0.8.2: сравнительные листы и якоря фото

Служебная таблица из двух панелей «артикул / фото / наименование» больше не
отклоняет заказ, если в ней нет ни одного артикула из расчётных строк. Название
листа не используется как исключение. Если в такой таблице встречается
импортируемый артикул или его нельзя проверить из-за отсутствующего кэша формулы,
неоднозначность остаётся ошибкой. Состав товара не угадывается по соседнему столбцу.

При привязке изображения учитываются высота строки и смещение якоря DrawingML,
в том числе смещение за границы указанной строки. Скрытые строки сохраняют свою
логическую высоту. Незначительный краевой выход допустим в пределах одновременно
4 пунктов и 2% высоты картинки; существенное пересечение разных товаров отклоняется.

На двух предоставленных письмах проверены 23 товара и 23 фото, включая обновление
и повтор без изменения книги. Сами письма и вложения не включаются в репозиторий.
Полные файлы: `docs/fix-0.8.2-code.md`, проверки: `docs/fix-0.8.2-validation.md`.


## Исправление 0.8.3: фото, сохранённое только внешней ссылкой

Внешняя ссылка без встроенных байтов картинки больше не отклоняет всё вложение.
Товар импортируется с предупреждением PHOTO_EXTERNAL_LINK, доступные встроенные фото
переносятся как обычно. Прежнее фото сохраняется при отсутствии нового; старое фото,
которое тоже является внешней ссылкой, сохраняется вместе с гиперссылкой и переносится
на новый сезонный лист. Новое встроенное фото заменяет прежнюю ссылку.
Самостоятельно скачивать картинки с внешних серверов программа не пытается.
Без байтов картинки внешнюю ссылку нельзя преобразовать в нативное изображение в ячейке;
она остаётся прежним привязанным объектом. Повреждённые встроенные фото и некорректные
связи по-прежнему являются ошибками.

Проверки и ограничения: `docs/fix-0.8.3-validation.md`.
Полные новые и изменённые файлы: `docs/fix-0.8.3-code.md`.


## Исправление 0.8.4: восстановление активных фильтров при импорте

Устранена ошибка AutoFilter, отменявшая импорт при активном обычном фильтре.
Excel возвращает Operator=0 для одного критерия, но не принимает этот ноль обратно
как входной XlAutoFilterOperator. Неиспользуемые аргументы теперь действительно
пропускаются через IDispatch; массивы значений и вторые критерии сохраняются.
Фильтры по цвету захватываются как RGB, а не ссылки на объекты Excel.
Для Top/Bottom исходное количество/процент читается из сохранённой OOXML-книги:
COM возвращает вычисленный порог, который нельзя использовать как параметр Top Items.

Проверка в настоящем Excel: `tools/verify_filters_excel.py`.
Полные файлы: `docs/fix-0.8.4-code.md`; результаты: `docs/fix-0.8.4-validation.md`.

Перед заменой строк фильтрация временно снимается: End(xlUp) при активном фильтре
видит последнюю видимую строку и может выбрать неправильное место добавления.
После записи критерии восстанавливаются. До принятия рабочей копии проверяется
полный состав прежних артикулов и их расчётных/фото строк, а не только новые записи.

Копирование формата новой строки использует Copy с явным Destination внутри Excel;
пара Copy/PasteSpecial с системным буфером исключена. Транзитные значения очищаются,
фото-столбец копируется по свойствам без переноса нативной картинки предыдущего товара.
````

## docs/architecture/decisions.md

````markdown
# Архитектурные решения

## Слои и зависимости

Domain зависит только от стандартной библиотеки: dataclass-модели, инварианты,
происхождение записи, отчёт. Application содержит сценарии и порты Protocol.
Infrastructure реализует работу с конфигурацией, Office, файлами и журналированием.
Presentation преобразует пользовательский ввод в вызовы приложения.
`app.py` — composition root; его диагностический сценарий относится к этапу 1.

Каждый адаптер отвечает за одну внешнюю систему. Outlook/Excel не импортируются
в Domain и не передают COM-объекты в модели. Объекты Office живут в потоке с
инициализированным COM; GUI получает события через очередь и tkinter.after.

## Формат настроек

TOML читается штатным tomllib Python 3.12. Загрузка строгая: неизвестные ключи,
неверные типы, конфликты псевдонимов и вкладок приводят к ConfigurationError.
Настройки и маршруты неизменяемы. Сезон — расширяемая строка, не закрытый enum.
Выбор пары реализован отдельным сервисом этапа 4; загрузчик только проверяет настройки.

## Модели и данные

Артикул — строка, ведущие нули и регистр сохраняются. Текстовые поля не преобразуются
в формулы Excel. ProductRecord содержит копию словаря значений с запретом изменений,
ссылку на письмо/вложение и координаты исходной строки.
Фото имеет хеш нормализованных пикселей; извлечение реализовано на этапе 5.
ReceivedTime должен преобразовываться адаптером в datetime с часовым поясом.
Денежные значения могут храниться в Decimal; NaN и бесконечность недопустимы.

## Office и запись

openpyxl предназначен для чтения подходящих OOXML-вложений. Общую книгу с объектами
и нативными изображениями в ячейке будет сохранять Excel через xlwings/pywin32.
Конкретный API изображений и сохранение после повторного открытия проверяются
на Office 2024 и Microsoft 365 до приёмки этапа 5–6.
xlwings pictures.add с anchor само по себе не доказывает режим изображения в ячейке.

Источник формул поставщика импортируется как вычисленные значения; если кеша нет,
на этапе 3 строка получает ошибку. Источник нужно пересчитать в Excel и получить заново.
Политика защищённых файлов будет определена по фактическим входам.

Две строки сезонной пары представляют один товар. Индексы дублей учитывают эту пару,
а не объявляют зеркальные строки конфликтом. Изменение сезона — согласованный перенос
обоих представлений с сохранением прежнего фото, если новое не пришло.

Корректные вложения отделяются от ошибочных до записи. План, резервная копия,
проверка состояния исходной книги, запись в рабочую копию и проверка сохранённого
результата должны предшествовать замене общего файла. Гарантии восстановления
подтверждаются fault-injection испытаниями; Excel сам по себе не транзакционная БД.
В этапе 1 книги только проверяются на чтение и никогда не изменяются.

## Логи и доставка

Loguru: UTF-8, ротация по размеру, хранение по сроку. diagnose/backtrace выключены,
чтобы исключения не выводили значения локальных переменных. Содержимое писем не
логируется автоматически. CLI отключает стандартный stderr-sink Loguru; каждый
экземпляр приложения при завершении освобождает только свой файловый sink.

Настоящие письма, книги и резервные копии не включаются в Git. Фиксированные версии
проверенного окружения хранятся отдельно от диапазонов совместимости.
Сборка EXE, пользовательские каталоги, обновления и подпись относятся к этапу 8.

## Этап 2: источник Outlook

MailSource и CaptureManifestStore — порты Application. CaptureMail создаёт отдельный
каталог UUID, вызывает источник и сохраняет манифест. Данные MailCapture содержат
идентичности, позицию в выделении, пути и контрольные суммы; COM-объектов в них нет.

Адаптер подключается через GetActiveObject только к уже запущенному классическому
Outlook. COM инициализируется STA в вызывающем потоке и освобождается в finally.
Состав выделения считывается до обработки вложений. Объекты другого класса
пропускаются с предупреждением. Ошибки отдельных писем/вложений становятся issues.

Дата получения читается из PR_MESSAGE_DELIVERY_TIME (PT_SYSTIME) и сохраняется
как UTC; локальный ReceivedTime не используется для повторной конвертации времени.
Имена сохранённых файлов генерируются по индексам; исходное имя — только метаданные.
Временный файл публикуется после проверки размера и вычисления SHA-256.
Сохранение вложений не означает, что Excel-содержимое уже проверено или импортировано.

JSON-отчёт связывает сохранённые файлы с письмами. Сбой отчёта оставляет вложения
для восстановления и вызывает явную ошибку. Тема, адрес и идентификаторы писем
сохраняются только в локальном манифесте; логи содержат номера позиций и коды ошибок.
Тела писем не читаются. Новый запуск не перезаписывает предыдущий.

Из-за отсутствия настроенного Outlook здесь интеграционная приёмка перенесена
на другое устройство по согласованию с пользователем. Это не блокирует разработку
следующих этапов, но остаётся обязательной частью приёмки приложения.

## Этап 3: чтение Excel и нормализация

WorkbookReader возвращает модели SourceSheet/SourceCell без объектов библиотек.
OOXML читается дважды: формулы и сохранённые значения. Это позволяет различать
пустой результат строковой формулы и отсутствующий кеш. LegacyReader изолирует
COM-чтение XLS/XLSB, открывает отдельный экземпляр Excel и закрывает его в finally.

NormalizeWorkbook и ColumnRegistry работают только с моделями Domain. Словарь
псевдонимов загружается отдельным TOML-адаптером. Заголовки связываются с полями,
неизвестные столбцы сохраняются; фото-описания соединяются по артикулу.
Нестандартные шаблоны требуют явного профиля, а не угадывания обязательных полей.

ExcelErrorValue хранит код ошибки как самостоятельный тип. Он допустим в строке
товара по согласованному правилу; будущий адаптер записи должен восстановить ошибку
Excel, а не записать её строковое название. Decimal и даты также сериализуются
с явным типом. Предпросмотр сохраняет источник, строку, тему и дату письма.

Ошибки чтения отдельной книги не останавливают другие книги. Повреждение манифеста
или нарушение контрольных сумм останавливает предпросмотр до чтения: происхождение
данных должно быть достоверным. Предпросмотр не выбирает сезонную пару и не записывает
общую книгу. Метка eligible_for_import означает только отсутствие ошибок чтения;
окончательную готовность определят следующие этапы.

## Этап 4: маршрутизация строк

SeasonRoute перенесён в Domain; Infrastructure сохраняет совместимый импорт этого
типа для прежнего кода. Application не зависит от настроек Infrastructure.
ResolveSeason строит неизменяемый индекс настроенных псевдонимов, разбирает наблюдавшиеся
пометки/номер/год и возвращает SeasonAssignment с причиной выбора пары.
sales_month отвечает только за распознавание однозначного месяца, без обращения к Office.

RouteWorkbook сохраняет исходные ProductRecord и ошибки всех строк. Неизвестное
назначение представлено явно; одна такая строка исключает всё вложение из кандидатов.
Зимняя строка без определимого месяца допускается с предупреждением согласно решению
пользователя. Модели сезонных назначений не меняют исходные данные и не создают вкладки.

preview-seasons использует тот же адаптер чтения, что preview-excel. Отчёт содержит
исходный сезон и назначение отдельно, чтобы будущий writer использовал итоговый сезон
и точные имена пары, сохраняя происхождение данных. Подсчёт назначений отделён от числа
товаров в пригодных вложениях. Ни один из этих счётчиков не означает сохранение книги.
Год назначения при переходе из декабря повышается на один по уточнению пользователя.
Сначала берётся год из сезона, при его отсутствии — из даты начала продаж.
Если ни один источник года недоступен, назначение Весны сохраняется с предупреждением.

## Этап 5: фотографии

Domain описывает исходное изображение с координатами/обрезкой и решение add/replace/keep/none.
BindPhotos зависит от порта PhotoAssetStore, связывает фото-ячейку с артикулом и
не получает объекты Pillow/Excel. Повреждение фото становится ошибкой вложения;
отсутствие изображения остаётся допустимым None и сохраняет старое фото при обновлении.

OOXMLPackage читает части и внутренние связи с лимитами размера. DrawingPhotos
разбирает обычные привязки, RichPhotos — цепочку метаинформации нативных ячеек.
PhotoReader объединяет результаты; legacy-книги преобразуются только в временные
копии. Источники не сохраняются, внешние изображения не скачиваются.

PhotoStore реализует Pillow-преобразования и контентное хранение PNG. Размеры и RGBA
пиксели входят в хеш. Несколько разных фотографий образуют детерминированный коллаж;
исходное расположение вне фото-столбца не используется для угадывания привязки.

InCellPictureWriter — COM-адаптер для рабочей копии будущего writer. В проверенном
Microsoft 365 необходимы активация/выделение и начальная конвертация; затем прямая
вставка восстанавливает исходные пиксели, поскольку одна конвертация растеризует
картинку до размеров shape. Сохранённая rich-data связь и хеш проверены после reopen.
Это проверенное поведение конкретной сборки, не гарантия всей матрицы Office.
Все сеансы Excel в сценарии должны выполняться последовательно; общую книгу
можно заменять только после полной проверки рабочей копии на этапе 6.

## Этап 6: общая книга и восстановление

Планирование, выбор полей и fingerprint находятся в Application и зависят только
от моделей Domain. Поддерживаемые типы ошибок передаются как возможности адаптера:
неподдерживаемая ошибка в записываемом поле исключает вложение до начала записи.
Чтение файлов, Excel COM, резервные копии и журнал транзакции находятся в Infrastructure.

PreparedAttachment хранит маршрутизированные товары, ошибки и известные артикулы,
включая товары отклонённого вложения. SelectLatest не допускает применения старого
письма после ошибки нового. Если список артикулов ошибочного файла неполон, более
старые кандидаты блокируются: невозможно доказать, что они не относятся к этому файлу.
Равные времена и отличающиеся данные образуют явный конфликт.

MasterSnapshot читает все распознанные товарные листы, включая ненастроенные пары,
кроме исключённых листов и собственного состояния. Индекс артикулов хранит две
зеркальные строки как один товар. Заголовки связываются по именам; неоднозначные
существующие строки не удаляются автоматически. Отсутствие целевой пары исключает
целое вложение. Дополнительные поля без целевого заголовка перечисляются в отчёте.
Одна однозначная существующая строка восстанавливается до полной пары с предупреждением;
ссылки сохраняемых фото-формул учитывают настроенную расчётную вкладку прежнего фото-листа.

MasterWriter изменяет только копию через собственный последовательный STA-сеанс
Excel. Перед открытием включаются запрет макросов/событий и ручной расчёт. Строки
сохраняются по ролям, удаляются снизу вверх, затем вставляются заново. Формулы
в отсутствующих полях восстанавливаются через FormulaR1C1; ссылки на прежнюю
расчётную вкладку при переносе сезона меняются посредством токенизации формулы,
без замены текста в строковых литералах. Служебные формулы восстанавливаются;
фильтры получают расширенный диапазон и прежние поддержанные критерии.

Входящие строки записываются как текст с временным текстовым форматом, поэтому
значение, начинающееся с '=', не становится формулой. ExcelErrorValue превращается
в собственную постоянную ошибку, вычисляется и заменяется её типизированным значением:
VT_ERROR в COM setter этой сборки ошибочно интерпретируется как пропущенный аргумент.
Даты записываются как серийные числа с учётом систем 1900/1904 и локальных кодов
формата Application.International. Финальная проверка повторно читает сохранённую
книгу и rich-data изображения, сравнивает поля и хеши пикселей.

Ручной расчёт действует только во время записи. После закрытия собственного Excel
адаптер возвращает исходный calcMode в единственном XML-элементе calcPr, не меняя
остальные части ZIP-пакета, пространства имён и rich-data. Для автоматического
режима пересчёт откладывается до обычного открытия книги пользователем.

_KL_IMPORT_STATE хранит артикул, точное время письма в UTC и fingerprint входящих
данных. Состояние сохраняется в той же книге и той же транзакции: отдельный JSON
индекс не может рассинхронизироваться с сохранёнными строками. Повторное письмо
не создаёт дублей; более старая версия не заменяет новую. Для исходной вручную
собранной книги без состояния доступная календарная дата защищает от старых писем.
Точное время исторической строки восстановить невозможно.

WorkbookTransaction использует lock с PID/run_id, проверяемый backup, рабочую копию
в папке общей книги, проверку исходного SHA-256 и os.replace после закрытия Excel.
Журнал prepared/ready/committed и хеши позволяют отличить незавершённую подготовку
от уже заменённого файла даже после сбоя обновления журнала. Счётчики сохранённых
товаров формируются после commit. Ошибка JSON-отчёта не выдаётся за откат уже
сохранённой книги. restore-backup отказывает при последующих ручных изменениях;
recover-lock разрешён только для завершившегося владельца соответствующего журнала.


## Этап 7: tkinter и фоновые операции

Tk вызывается только в главном потоке. GuiWorker владеет одним не-daemon потоком;
он выполняет полный цикл Outlook/Excel и передаёт через Queue обычные dataclass-события.
COM-адаптеры инициализируют STA в том потоке, где работают. Окно опрашивает очередь
через after и не делает join во время импорта. Двойной запуск запрещён до получения
терминального события. Файловая блокировка этапа 6 защищает книгу и между процессами.

JobControl принадлежит Application и не зависит от tkinter. Перед записью Lock
упорядочивает отмену и вход в необратимый для отмены участок. После этой границы
запрос отмены не прерывает транзакцию. Во время подготовки отмена кооперативная:
Office-вызов не прерывается посередине. Закрытие окна ожидает завершения работника.

Личные настройки сохраняются атомарно с повторным чтением и полной валидацией.
Редактор синонимов сохраняет отдельный columns.local.toml, не меняя общие настройки.
GuiResult объединяет результат записи, сообщения получения писем и путь манифеста.
Ошибки получения выделения не скрываются за успешным результатом записи.


## Этап 8: Windows-дистрибутив

Одна Analysis PyInstaller формирует GUI и консольный EXE с общими библиотеками
в _internal. Это формат one-folder: переносится вся папка, не один EXE.
Только три стандартных TOML включаются как ресурсы; рабочие данные и локальные
настройки сборщик не захватывает. Версия записана в package, pyproject и PE-ресурсах.

Bootstrap различает каталог ресурсов PyInstaller и профиль Windows. Первый запуск
атомарно создаёт недостающие файлы в LOCALAPPDATA/KuchenlandImporter, затем использует
их без автоматического перезаписывания. Журналы и backup находятся вне папки EXE.
Явный --config всегда имеет приоритет. Исходники продолжают использовать config
проекта независимо от текущего каталога. Путь _MEIPASS и формат spec основаны
на официальных [правилах PyInstaller](https://pyinstaller.org/en/stable/runtime-information.html)
и [spec files](https://pyinstaller.org/en/stable/spec-files.html).

Сборка использует отдельные закреплённые requirements-build и runtime lock;
конкретные версии, хеши файлов и исходников помещаются в release-manifest.json.
Существующий выпуск не перезаписывается. ZIP содержит одну папку со всем комплектом,
инструкцией и лицензиями; рядом находится SHA-256. Побитовая воспроизводимость
архива не заявляется из-за времён файлов и особенностей PE.

Проверка запуска GUI создаёт настоящее окно Tk, проверяет доступность кнопок
и записывает JSON, затем закрывается. Она используется для проверки упакованного
Tcl/Tk, не подменяет приёмку взаимодействия с Outlook. Консольный EXE проверяется
в отдельном профиле с PATH без Python, затем выполняет импорт на проверочной копии.


При приёмке текущего Excel 16.0.20326.20232 зафиксировано аварийное завершение
во время оформления строки. Полное Rows.Copy заменено ограниченными диапазонами
с исключением нативной фото-ячейки из буфера. Фото-формат копируется отдельно,
с Pattern и LineStyle последними для точного сохранения пустой заливки и границ.
Сбой Close/Quit не скрывает первоначальную причину отказа; при отсутствии основной
ошибки сбой закрытия прерывает транзакцию. Принудительное завершение Excel и
автоматический повтор записи не применяются.


## 0.8.1: чтение общей книги и вложений

ReadLimits отделяет структурные бюджеты OOXML от физического размера XLSX/XLSM.
Жёсткая проверка 50 МБ удалена из WorkbookReader и OOXMLPackage. Профиль исходного

Preflight ZIP выполняется до openpyxl, чтобы ошибочный источник отклонялся до
выделения памяти на распаковку. Ограничения XML-частей и медиачастей остаются.
Ошибки транзакции включают фазу и имя исходной общей книги, а не имя временной копии.


## 0.8.2: роль исходных листов и логические координаты изображений

SourceTables сначала распознаёт расчётные таблицы по article/supplier/season,
собирает их идентификаторы, затем выделяет фото-таблицы. Сравнительная таблица
с несколькими панелями article/photo/name пропускается с предупреждением только
при доказанном отсутствии пересечения с импортируемыми артикулами. Ошибки
неоднозначной основной таблицы и связанной фото-таблицы сохраняются. Одинаковый
индекс используется нормализацией, привязкой фото и сбором известных артикулов,
чтобы служебный лист не объявлял все идентификаторы письма неизвестными.
ArticleIdentity выделен отдельно с сохранением прежнего публичного импорта функции.

RowGeometry обрабатывает перенос смещения от начала строки для обоих типов якорей
DrawingML. Видимость/фильтр строки не меняет артикул: применяется логическая высота ht.
Субпиксельный/краевой выход в соседнюю строку не создаёт второго товара, если он
не больше одновременно 4 pt и 2% высоты изображения. Значительное пересечение
по-прежнему передаётся проверке PHOTO_SPANS_PRODUCTS. Эти правила проверены на новых
и прежних реальных вложениях, а также на искусственных однозначных/неоднозначных случаях.


## 0.8.3: внешние ссылки на изображения

PhotoProblem различает корректную внешнюю ссылку без встроенных байтов и повреждение.
BindPhotos считает первое предупреждением об отсутствии фото, не второе.
ExistingProduct хранит идентификаторы прежних внешних объектов отдельно от PhotoAsset.
Внешняя ссылка не является изображением с известным хешем пикселей.
LinkedPhotoKeeper изолирует заменяемые внешние объекты до открытия рабочей копии Excel;
ссылки возвращаются в OOXML после сохранения, с уникальными ID и новыми координатами.
Неподдерживаемые зависимости вызывают отказ рабочей копии, а не потерю фотографии.
Исходные URL не загружаются Python-кодом и не включаются в публичные отчёты.
После записи проверяется наличие каждого сохранённого внешнего объекта.


## 0.8.4: параметры AutoFilter не всегда пригодны для обратной передачи

master_filters использует IDispatch без автоматических значений обёрток pywin32.
Operator=0 опускается; для пропусков между аргументами передаётся VARIANT VT_ERROR
с DISP_E_PARAMNOTFOUND. PyOleMissing предназначен для InvokeTypes и не подходит
для обычного Invoke. Цвет вычисляется до удаления исходного фильтра.
filter_metadata читает исходный val и режим Top/Bottom из сохранённого OOXML;
вычисленный COM-порог не подменяет исходное количество элементов/процентов.
Ошибки восстановления сохраняют контекст листа, поля и диапазона и вызывают откат
рабочей копии, а не отключение пользовательского фильтра.

Перед capture_rows/delete_rows/append_row вызывается suspend_filters: ShowAllData
для фактически фильтруемых листов. На нативном Excel подтверждено, что End(xlUp)
при фильтрации возвращает последнюю видимую строку, а не последнюю строку данных.
verify_inventory сравнивает мультимножество (артикул, лист) с исходным снимком,
заменяя только явно записанные товары на их новые пары листов. Потеря, дубликат
````

````markdown
1. Распакуйте ZIP целиком в отдельную папку на локальном диске.
````

````python
"""Read saved Top/Bottom filter parameters which the Excel COM getter does not expose."""

from pathlib import Path

from kuchenland_importer.infrastructure.excel.ooxml_package import OOXMLPackage, S
from kuchenland_importer.infrastructure.excel.read_limits import MASTER_LIMITS


def read_top_filters(path: Path) -> dict[tuple[str, int], tuple[int, str]]:
    result = {}
    package = OOXMLPackage(path, limits=MASTER_LIMITS)
    try:
        for name, part in package.sheets():
            for column in package.xml(part).findall(f"{{{S}}}autoFilter/{{{S}}}filterColumn"):
                top = column.find(f"{{{S}}}top10")
                if top is None:
                    continue
                is_top = top.attrib.get("top", "1") in {"1", "true"}
                percent = top.attrib.get("percent", "0") in {"1", "true"}
                operator = (3 if is_top else 5) + int(percent)
                result[(name, int(column.attrib["colId"]) + 1)] = (operator, top.attrib["val"])
    finally:
        package.close()
    return result
````

## src/kuchenland_importer/infrastructure/excel/master_filters.py

````python
"""Extend existing AutoFilter ranges and reapply the user's supported criteria."""

from pathlib import Path
from typing import Any

import pythoncom
from win32com.client import VARIANT

from kuchenland_importer.domain.master import MasterSnapshot
from kuchenland_importer.infrastructure.excel.filter_metadata import read_top_filters

# IDispatch optional argument, unlike VT_EMPTY or the InvokeTypes-only PyOleMissing.
MISSING = VARIANT(pythoncom.VT_ERROR, -2147352572)  # DISP_E_PARAMNOTFOUND


def capture_filters(
    book: Any, master: MasterSnapshot
) -> dict[str, tuple[int, int, int, list[dict[str, Any]]]]:
    result = {}
    top_filters = None
    for name in master.layouts:
        sheet = book.Worksheets(name)
        if not sheet.AutoFilterMode:
            continue
        auto = sheet.AutoFilter
        area = auto.Range
        filters = []
        for field in range(1, auto.Filters.Count + 1):
            item = auto.Filters(field)
            if not item.On:
                continue
            criteria: dict[str, Any] = {"Field": field, "Operator": item.Operator}
            for key in ("Criteria1", "Criteria2"):
                try:
                    criteria[key] = getattr(item, key)
                except Exception:
                    continue  # Excel omits the unused side of a one-sided filter.
            if criteria["Operator"] in {8, 9} and "Criteria1" in criteria:
                # Excel returns Interior/Font objects, not the input RGB integer.
                # Resolve Color while the original filter COM object is still valid.
                color = criteria["Criteria1"]
                criteria["Criteria1"] = int(color if isinstance(color, int) else color.Color)
            if criteria["Operator"] in {3, 4, 5, 6}:
                # COM reports the computed threshold (e.g. >=70), not the requested
                # number/percentage (e.g. top 3). Recover the original saved parameter.
                if top_filters is None:
                    top_filters = read_top_filters(Path(str(book.FullName)))
                saved = top_filters.get((name, field))
                if saved is None or saved[0] != criteria["Operator"]:
                    raise ValueError(f"Нет сохранённых параметров Top/Bottom фильтра {name}, "
                                     f"поле {field}.")
                criteria["Criteria1"] = saved[1]
                criteria.pop("Criteria2", None)
            if not {"Criteria1", "Criteria2"} & criteria.keys():
                raise ValueError(f"Невозможно сохранить критерий фильтра {name}, поле {field}.")
            filters.append(criteria)
        result[name] = (int(area.Row), int(area.Column), int(area.Columns.Count), filters)
    return result


def restore_filters(
    book: Any,
    master: MasterSnapshot,
    filters: dict[str, tuple[int, int, int, list[dict[str, Any]]]],
) -> None:
    for name, (header, column, width, criteria) in filters.items():
        sheet = book.Worksheets(name)
        layout = master.layouts[name]
        last = max(
            header + 1, int(sheet.Cells(sheet.Rows.Count, layout.columns["article"]).End(-4162).Row)
        )
        sheet.AutoFilterMode = False
        area = sheet.Range(sheet.Cells(header, column), sheet.Cells(last, column + width - 1))
        sheet.Activate()
        # Invoke with truly omitted arguments; generated wrappers inject invalid defaults
        # for this optional-argument method on some localized Office builds.
        dispatch_id = area._oleobj_.GetIDsOfNames("AutoFilter")
        try:
            area._oleobj_.Invoke(dispatch_id, 0, 1, True)
        except Exception as error:
            raise ValueError(f"Не удалось восстановить фильтр {name}: {area.Address}") from error
        for condition in criteria:
            apply_criteria(area, condition, sheet_name=name)


def apply_criteria(area: Any, condition: dict[str, Any], *, sheet_name: str) -> None:
    # Filter.Operator returns zero for one criterion. Zero is not a valid input
    # XlAutoFilterOperator: omit it rather than replaying it or injecting xlAnd.
    arguments = [
        condition["Field"],
        condition.get("Criteria1", MISSING),
        condition.get("Operator") or MISSING,
        condition.get("Criteria2", MISSING),
    ]
    while arguments and arguments[-1] is MISSING:
        arguments.pop()
    try:
        dispatch_id = area._oleobj_.GetIDsOfNames("AutoFilter")
        area._oleobj_.Invoke(dispatch_id, 0, 1, True, *arguments)
    except Exception as error:
        raise ValueError(
            f"Не удалось восстановить критерий фильтра {sheet_name}: "
            f"поле {condition['Field']}, диапазон {area.Address}"
        ) from error


def suspend_filters(book: Any, filters: dict[str, Any]) -> None:
    """Expose filtered rows before End(xlUp), row replacement and picture insertion."""
    for name in filters:
        sheet = book.Worksheets(name)
        if sheet.FilterMode:
            try:
                sheet.ShowAllData()
            except Exception as error:
                raise ValueError(f"Не удалось временно снять фильтрацию листа {name}.") from error
````

````python
                if sheet.ProtectContents:
                    raise ValueError(f"Лист {name} защищён.")
                fields = product_fields(item, is_photo)
                fields = {key: value for key, value in fields.items() if key in layout.columns}
                row = append_row(sheet, layout)
                restore_absent(
                    sheet,
                    row,
                    layout,
                    preserved.get((item.product.article, is_photo), {}),
                    set(fields),
                    preserve_manual=preserve_manual,
                    formula_routes={
                        (
                            master.layouts[old.sheet].calculation_sheet or old.sheet
                        ): route.calculation_sheet
                        for old in action.previous.rows
                        if "photo" not in master.layouts[old.sheet].columns
                        or master.layouts[old.sheet].calculation_sheet is not None
                    }
                    if action.previous
                    else {},
                )
                for key, value in fields.items():
                    write_value(sheet.Cells(row, layout.columns[key]), value)
                if is_photo and asset is not None:
                    cell = sheet.Cells(row, layout.columns["photo"])
                    if cell.RowHeight < 60:
                        cell.RowHeight = 100
                    InCellPictureWriter().place(sheet, str(cell.Address), asset)
                if is_photo:
                    cell = sheet.Cells(row, layout.columns["photo"])
                    linked_names = linked.restore(item.product.article, sheet, cell)
                rows.append(row)
            written.append(
                WrittenProduct(
                    item.product.article,
                    route.calculation_sheet,
                    rows[0],
                    route.photo_sheet,
                    rows[1],
                    asset.pixel_sha256 if asset else None,
                    decision,
                    linked_names,
                )
            )
            if len(written) % 10 == 0 or len(written) == len(plan.products):
                logger.info("Запись товаров: {} из {}", len(written), len(plan.products))
            if progress:
                progress(len(written), len(plan.products))
        restore_service(book, service)
        restore_filters(book, master, filters)
        save_state(book, master, plan)
        book.Save()
    linked.finish(path)
    restore_calculation_mode(path, master.calculation_mode)
    return tuple(written)
````

````python
"""Format new empty rows with direct Excel copies, without using the OS clipboard."""

from typing import Any

from kuchenland_importer.domain.master import SheetLayout


def copy_row_format(sheet: Any, source_row: int, target_row: int, layout: SheetLayout) -> None:
    last_column = max(layout.columns.values())
    photo_column = layout.columns.get("photo")
    spans = (
        [(1, last_column)]
        if photo_column is None
        else [(1, photo_column - 1), (photo_column + 1, last_column)]
    )
    for first, last in spans:
        if first > last:
            continue
        source = sheet.Range(sheet.Cells(source_row, first), sheet.Cells(source_row, last))
        target = sheet.Range(sheet.Cells(target_row, first), sheet.Cells(target_row, last))
        copy_objects = sheet.Application.CopyObjectsWithCells
        try:
            sheet.Application.CopyObjectsWithCells = False
            # Destination avoids Copy/PasteSpecial's shared clipboard and timing.
            # The caller provides a new empty row; discard transient copied values.
            source.Copy(Destination=target)
            target.ClearContents()
        except Exception as error:
            raise ValueError(
                f"Не удалось перенести формат новой строки {sheet.Name}: "
                f"{source.Address} → {target.Address}"
            ) from error
        finally:
            sheet.Application.CopyObjectsWithCells = copy_objects
    if photo_column is not None:
        source = sheet.Cells(source_row, photo_column)
        target = sheet.Cells(target_row, photo_column)
        style = source.Style
        target.Style = style if isinstance(style, str) else style.Name
        for name in ("NumberFormatLocal", "HorizontalAlignment", "VerticalAlignment", "WrapText"):
            setattr(target, name, getattr(source, name))
        for name in ("Color", "PatternColor", "Pattern"):
            setattr(target.Interior, name, getattr(source.Interior, name))
        for border in (7, 8, 9, 10):
            old, new = source.Borders(border), target.Borders(border)
            for name in ("Weight", "Color", "LineStyle"):
                setattr(new, name, getattr(old, name))
    sheet.Rows(target_row).RowHeight = sheet.Rows(source_row).RowHeight
````

````python
def equal_value(expected: CellValue, actual: object) -> bool:
    if expected is None or expected == "":
        return actual is None or actual == ""
    if isinstance(expected, Decimal):
        return isinstance(actual, float | int) and abs(float(expected) - actual) <= max(
            1e-9,
            abs(float(expected)) * 1e-12,
        )
    if isinstance(expected, datetime):
        return (
            isinstance(actual, datetime)
            and abs((expected.replace(tzinfo=None) - actual).total_seconds()) < 0.001
        )
    if isinstance(expected, date):
        return actual == expected or isinstance(actual, datetime) and actual.date() == expected
    if isinstance(expected, float):
        return isinstance(actual, float | int) and abs(expected - actual) <= max(
            1e-9,
            abs(expected) * 1e-12,
        )
    return expected == actual


def verify_master(
    path: Path,
    master: MasterSnapshot,
    plan: WritePlan,
    written: tuple[WrittenProduct, ...],
    directory: Path,
) -> None:
    verify_inventory(path, master, written)
    book = load_workbook(path, read_only=False, data_only=False)
    try:
        for action, saved in zip(plan.products, written, strict=True):
            for name, row, photo in (
                (saved.calculation_sheet, saved.calculation_row, False),
                (saved.photo_sheet, saved.photo_row, True),
            ):
                sheet = book[name]
                layout = master.layouts[name]
                for key, value in product_fields(action.incoming, photo).items():
                    if key not in layout.columns:
                        continue
                    cell = sheet.cell(row, layout.columns[key])
                    if isinstance(value, ExcelErrorValue):
                        valid = cell.data_type == "e" and cell.value == value.code
                    else:
                        valid = cell.data_type != "f" and equal_value(value, cell.value)
                    if not valid:
                        raise ValueError(
                            f"Проверка записи не пройдена: {name}!{cell.coordinate}; "
                            f"ожидалось {value!r}, получено {cell.value!r}"
                        )
    finally:
        book.close()
    extraction = PhotoReader().read(path, limits=MASTER_LIMITS)
    photos = {(p.sheet, p.row, p.column): p for p in extraction.pictures if p.native}
    store = PhotoStore(directory)
    linked = {
        (p.sheet, p.row, p.column, p.shape_name)
        for p in extraction.problems if p.external_link
    }
    for saved in written:
        column = master.layouts[saved.photo_sheet].columns["photo"]
        if any(
            (saved.photo_sheet, saved.photo_row, column, name) not in linked
            for name in saved.linked_photo_names
        ):
            raise ValueError(f"Прежняя внешняя ссылка на фото не сохранена: {saved.article}")
        if saved.photo_digest is None:
            continue
        column = master.layouts[saved.photo_sheet].columns["photo"]
        picture = photos.get((saved.photo_sheet, saved.photo_row, column))
        if picture is None or store.build((picture,)).pixel_sha256 != saved.photo_digest:
            raise ValueError(f"Нативное фото не прошло проверку: {saved.article}")


def verify_inventory(
    path: Path, master: MasterSnapshot, written: tuple[WrittenProduct, ...]
) -> None:
    """Verify every old article/mirror remains, except explicitly replaced product rows."""
    replaced = {product.article for product in written}
    expected = Counter(
        (article, row.sheet)
        for article, product in master.products.items() if article not in replaced
        for row in product.rows
    )
    for saved in written:
        expected.update(
            ((saved.article, saved.calculation_sheet), (saved.article, saved.photo_sheet))
        )
    actual: Counter[tuple[str, str]] = Counter()
    book = load_workbook(path, read_only=True, data_only=True)
    try:
        for name, layout in master.layouts.items():
            column = layout.columns["article"]
            for (cell,) in book[name].iter_rows(
                min_row=layout.first_row, min_col=column, max_col=column
            ):
                if cell.value is not None and cell.value != "":
                    actual[(article_value(SourceCell(cell.value)), name)] += 1
    finally:
        book.close()
    if actual != expected:
        missing = sum((expected - actual).values())
        extra = sum((actual - expected).values())
        raise ValueError(
            f"Проверка сохранности артикулов не пройдена: отсутствует строк {missing}, "
            f"лишних строк {extra}. Рабочая копия не будет принята."
        )
````
