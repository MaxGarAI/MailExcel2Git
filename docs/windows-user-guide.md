# Kuchenland Importer 0.9.0 — инструкция Windows

## Установка и запуск

1. Распакуйте ZIP целиком в отдельную папку на локальном диске.
2. Запускайте KuchenlandImporter.exe. Папка _internal должна оставаться рядом.
3. Выберите существующую общую книгу XLSX/XLSM; закройте её в Excel.
4. В классическом Outlook выделите нужные письма с Excel-вложениями.
5. Нажмите «Импорт из Outlook», дождитесь результата, проверьте сообщения.

Python устанавливать не нужно. Требуются Windows x64 и установленный настольный
Microsoft Excel; для получения писем — классический Outlook с настроенной учётной
записью. Новый Outlook не предоставляет используемый COM-интерфейс.
Поддержка Office 2024 и конкретной сборки Microsoft 365 проверяется на устройстве.
Сначала выполняйте импорт на отдельной копии общей книги.

В первый запуск программа создаёт конфигурацию и каталоги в
%LOCALAPPDATA%\KuchenlandImporter. В подпапке config находятся local.toml,
columns.toml, writing.toml и при изменении синонимов columns.local.toml.
В data находятся logs, backup, work, reports. Эти файлы не отправляются в GitHub.
Не удаляйте backup до проверки импортированной книги.

## Сезоны и столбцы

«Сезоны и вкладки» задаёт названия сезонов и соответствующую пару расчёт/ФОТО.
Можно добавить сезон; сами листы заранее создайте и оформите в Excel вручную.
Если пары нет, вложение пропускается целиком. Неизвестные сезоны требуют настройки.
«Названия столбцов» добавляет синонимы, например Item No → article.
Поля вложения без соответствующего столбца общей книги пропускаются.

## Результаты и отмена

Данные поступают в расчётную и фото-вкладку. При смене сезона старые строки удаляются.
Из нескольких писем побеждает новое. Одинаковое повторное письмо не создаёт дублей.
Ручные значения и формулы в отсутствующих полях сохраняются. Одинаковое фото
сохраняется, изменённое заменяется, отсутствие нового не удаляет прежнее.
Несколько разных фото одного товара образуют коллаж.

Окно показывает обработанные письма, добавленные/обновлённые/пропущенные товары
и фото. Ошибочные вложения пропускаются; корректные могут быть сохранены.
Откройте «Отчёт» и сообщения двойным щелчком. Число диагностик не равно числу
ошибочных вложений: у одного файла может быть несколько причин отказа.

«Отменить» действует на границах подготовки. Начатая запись и проверка книги
завершаются целиком. Закрытие окна дожидается работника; не завершайте процесс
через диспетчер задач во время записи. При зависшем Office не обещается мгновенная
отмена. Повторно запустить импорт во время работы нельзя.

## Восстановление и диагностика

«Восстановить книгу» принимает JSON-журнал из data\backup. Перед восстановлением
проверяются хеши; последующие ручные изменения книги не затираются. Если после
аварии осталась блокировка, используйте «Снять аварийную блокировку» и тот же журнал.
Работающий процесс не завершается. Резервную копию можно также открыть вручную
под другим именем для анализа. Подробности ошибок находятся в data\logs.

Консольная диагностика из PowerShell:

```powershell
.\KuchenlandImporter-cli.exe diagnose
.\KuchenlandImporter-cli.exe --version
```

Консольные команды поддерживают --config, --workbook, --data-dir; import-excel
требует --manifest. Restore-backup и recover-lock требуют --journal.
Коды выхода: 0 — успешно, 1 — частичные ошибки, 2 — ожидаемый отказ, 3 — непредвиденная
ошибка. Диагностика зависимостей не проверяет подключение Outlook и Excel.

«Из сохранённых вложений» принимает манифест, созданный capture-outlook, вместе
с исходной папкой вложений. Переносите всю папку, не меняйте файлы: проверяется SHA-256.
Произвольный XLSX без сведений о письме не является таким манифестом.

## Обновление и проверка комплекта

Распакуйте новую версию в новую папку. Личные данные в %LOCALAPPDATA% сохраняются.
Обновление не перезаписывает существующие личные настройки: новые маршруты
добавляйте через окно. ZIP сопровождается .sha256, файлы комплекта перечислены
в release-manifest.json. Сборка не подписана цифровой подписью; источник дистрибутива
следует проверять. Не отключайте системную защиту для запуска.

Приёмка перед ежедневной работой: выделение реальных писем, сохранение фото в ячейках,
сортировка/фильтры, перенос сезона, повторный импорт и восстановление backup.
Проверенная разработчиком сборка Office не заменяет приёмки на вашем устройстве.


## Согласование дополнительных полей (ветка 0.9.0)

Перед записью программа показывает новые непустые поля с примерами значений.
Выберите «Пропустить», «Связать с существующим» или «Создать справа».
Связывание использует внутренние имена полей, например `source:цвет`.
Новые заголовки должны иметь простое уникальное название без формул и разделителя ` / `.
Решения сохраняются отдельно для пути книги, поставщика и типа листа.
Сезонные листы одного типа используют общее правило; «ФОТО» согласуется отдельно.
Кнопка «Правила новых полей…» позволяет просмотреть и забыть решения.
Правила хранятся в `data/field-rules.json`, отдельно от исходников и общей книги.
CLI применяет существующие правила; неизвестные поля без GUI пропускаются как прежде.

Отмена окна отменяет весь импорт до записи. Правила сохраняются после завершения
согласования; при последующей ошибке книги они остаются для следующего запуска.
Пустые поля не вызывают отдельного вопроса. Новые столбцы добавляются справа на
листах с записываемыми товарами; существующие столбцы не переставляются.
Одинаковое время письма с изменённым сопоставлением подчиняется прежней проверке
MASTER_TIME_CONFLICT: существующие записи не переписываются молча.
