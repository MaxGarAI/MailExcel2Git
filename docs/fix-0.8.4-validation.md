# 0.8.4: активные фильтры и пакетный импорт

## Причина и воспроизведение

Новое MSG содержит одно Excel-вложение с одним товаром и одним встроенным фото.
Разбор таблицы, сезона и фото проходит без ошибок. Сбой находился на этапе записи
общей книги и не зависел от содержания этого письма.

На копии исходной общей книги включены обычные фильтры на расчётном и фото-листе.
EXE 0.8.3 воспроизвёл тот же HRESULT/AutoFilter из скриншота. При отказе SHA-256
книги сохранился. В нативном Excel отдельно подтверждено: Filter.Operator возвращает
0 для одного критерия; передача этого нуля как входного оператора вызывает ошибку.

Дополнительно проверено, что End(xlUp) при активном фильтре возвращает последнюю
видимую строку (в тесте 2 вместо 10). Это непригодно для определения места добавления.
В пакетной приёмке обнаружен также отказ PasteSpecial при форматировании новой строки.

## Изменения

- Оператор 0 опускается. Промежуточные необязательные параметры передаются как
  VARIANT VT_ERROR/DISP_E_PARAMNOTFOUND, без подстановок обёрток pywin32.
- Критерий цвета считывается в RGB до удаления исходного COM-фильтра.
- Top/Bottom: из OOXML читается исходное количество/процент val. COM возвращает
  вычисленный порог, который нельзя передавать как количество элементов.
- До изменения строк вызывается ShowAllData для фильтруемых листов. После записи
  восстанавливаются исходные критерии и расширяются диапазоны AutoFilter.
- Формат новых пустых строк копируется через Copy(Destination=...), без
  Copy/PasteSpecial. Транзитные значения очищаются, CopyObjectsWithCells возвращается
  в исходное состояние. Нативный фото-столбец по-прежнему форматируется отдельно.
- До атомарной замены проверяется полный состав (артикул, лист), включая все прежние
  товары. Потеря, лишняя строка или дубликат отклоняют рабочую копию.
- Ошибки фильтра/формата сохраняют контекст листа и диапазона; значения критериев
  не добавляются в текст ошибки. Ошибки не подавляются и фильтры не отключаются навсегда.

## Проверки

- 252 pytest-теста успешно; Ruff без ошибок; строгий Mypy — 96 модулей.
- tools/verify_filters_excel.py: 11 нативных сценариев — один критерий, пустые,
  непустые, несколько значений, AND/OR, диапазон дат, динамический фильтр,
  цвет ячейки/шрифта, Top Items. Снятие/восстановление, критерии, видимость строк
  и расширение диапазона проверены.
- tools/verify_master_excel.py: перенос сезона, сохранение/замена фото, отсутствие
  дублирования нативного фото при форматировании, фильтрация/сортировка, формулы,
  ручные значения, даты 1904, ошибки Excel, повтор, backup и восстановление успешно.
- Готовые GUI/CLI 0.8.4 запускаются без Python в PATH; хеши 1790 файлов и соответствие
  исходников проверены tools/verify_windows_package.py.

## Пакет 17 писем через окончательный EXE

Отдельная копия исходной общей книги, отдельный профиль; два активных обычных фильтра.
Пакет состоит из 13 прежних и четырёх недавно предоставленных писем.

| Результат | Количество |
|---|---:|
| Писем | 17 |
| Вложений допущено | 14 |
| Добавлено товаров | 79 |
| Обновлено товаров | 22 |
| Планово пропущено товаров | 17 |
| Добавлено фото | 78 |
| Заменено фото | 22 |
| Товаров без изменений при повторе | 101 |

Три вложения отклонены по существующим правилам неизвестного сезона / отсутствия пары
листов. Это отражено в отчёте; правила не ослаблялись. Ошибок IMPORT_ABORTED, AutoFilter
и PasteSpecial нет. Новое письмо явно проверено среди записанных товаров вместе с фото.
Полный состав прежних артикулов, значения и нативные фото записанных товаров прошли
проверку до commit. Критерии фильтров после сохранения совпали с исходными.
Повторный EXE-запуск оставил SHA-256 книги прежним, committed=false.
Контрольные суммы 19 исходных файлов (вложения, исходная книга и присланный MSG)
не изменились. Рабочие данные, письма, книги и журналы не публикуются.
